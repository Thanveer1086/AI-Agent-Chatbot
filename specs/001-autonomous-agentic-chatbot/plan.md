# Implementation Plan: Autonomous Agentic Chatbot with MCP Tools, Advanced RAG, and Modern UI

**Branch**: `001-autonomous-agentic-chatbot` | **Date**: 2026-11-12 | **Spec**: [spec.md](./spec.md)  

**Input**: Feature specification from `/specs/001-autonomous-agentic-chatbot/spec.md`  

---

## Summary

Build a greenfield, full-stack enterprise agentic chatbot that transforms traditional linear RAG into an **Autonomous Orchestrator Agent**. The system is built with a high-performance **FastAPI** backend orchestrating a **LangGraph** ReAct state graph, an asynchronous **Model Context Protocol (MCP)** gateway supporting multi-tool execution (parallel & sequential), an encapsulated **Advanced RAG tool** (Docling + PostgreSQL `pgvector` + `pg_trgm` BM25 + RRF + CrossEncoder reranking), and a sleek **Vite + React (TypeScript)** frontend featuring real-time Server-Sent Events (SSE) streaming, collapsible thought trace accordions, interactive citation drawers, and an admin knowledge management studio.

---

## Technical Context

**Language/Version**: 
- Backend: Python 3.11+
- Frontend: TypeScript 5.4+, React 18/19

**Primary Dependencies**:
- Backend: `fastapi`, `uvicorn`, `langgraph`, `langchain-core`, `pydantic>=2.0`, `asyncpg`, `httpx`, `mcp`, `docling`, `sentence-transformers`, `openai`, `google-genai`
- Frontend: `vite`, `react`, `react-dom`, `tailwindcss`, `@radix-ui/*` (shadcn/ui), `lucide-react`, `zustand`, `@tanstack/react-query`, `react-markdown`

**Storage**:
- Primary Database: PostgreSQL 15+ with `pgvector` (HNSW cosine similarity index) and `pg_trgm` (BM25 keyword search)
- Object/Blob Storage: Azure Blob Storage (or local filesystem fallback for development)

**Testing**:
- Backend: `pytest`, `pytest-asyncio`, `pytest-cov`, `httpx` (TestClient)
- Frontend: `vitest`, `@testing-library/react`

**Target Platform**:
- Multi-container Docker Compose stack (Linux Alpine/Debian containers)
- Deployable to Azure Container Apps, AWS ECS, or local workstation

**Project Type**:
- Full-Stack Web Application (Decoupled API Backend + Client SPA)

**Performance Goals**:
- Initial SSE streaming token delivery: $< 2.0$ seconds p90
- Parallel multi-tool execution speedup: $> 40\%$ reduction in tool wait time
- Hybrid vector/BM25 retrieval + rerank latency: $< 350$ms for top 20 candidates

**Constraints**:
- Max reasoning iterations: 5 loops
- Per-tool execution timeout: 15 seconds
- Zero hardcoded API keys or credentials
- 100% testable Pydantic v2 schemas across all API boundaries

**Scale/Scope**:
- 10+ concurrent user chat sessions with sub-second response start
- Hundreds of uploaded knowledge documents with up to 100,000 vector chunks

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Principle | Verification & Compliance | Gate Status |
| :--- | :--- | :--- |
| **I. Full-Stack Architectural Separation** | Frontend is a pure Vite React SPA communicating exclusively over HTTP REST and SSE streams. No database or backend code leaks into the client. | **PASS** |
| **II. Modularity & Domain Isolation** | Strict domain packages: `core/agent/`, `core/mcp/`, `core/rag/`, `core/db/`, and `api/`. Communication via typed interfaces. | **PASS** |
| **III. Asynchronous-First Execution** | `asyncpg` connection pool, `httpx` async client, `mcp` async client, and `asyncio.gather` for parallel multi-tool dispatch. | **PASS** |
| **IV. Real-Time Streaming & UX** | SSE streaming endpoint (`/api/chat/stream`) emitting tokens, thought steps, tool traces, and citations into collapsible shadcn/ui components. | **PASS** |
| **V. End-to-End Strict Type Safety** | Pydantic v2 models on backend; corresponding TypeScript interfaces on frontend. Zero untyped dictionaries or `any` types. | **PASS** |
| **VI. Zero-Trust Security & MCP Isolation** | Subprocess timeout enforcement (15s), circuit breaking, input guardrails, and environment variable secrets management. | **PASS** |
